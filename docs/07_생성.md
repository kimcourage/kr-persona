# 7. 생성

이 장은 페르소나 한 명이 센서스 기록에서 출발해 출력 파일에 적히기까지의 과정을 설명한다. 코드는 `krpersona/generate/`(생성기 `Gen4`, 금지 규칙, 재추출, 실행 스크립트)와 `krpersona/matraix/`(MatrAIx 그래프 샘플러 `KRSampler`, MatrAIx 금지 규칙의 분류와 거부 검사)에 있다. 조사 블록 모형의 추정은 6장, 일관성 규칙 묶음과 규칙에서 마스크를 만드는 컴파일은 8장, 검증은 9장에서 다룬다.

## 7.1 생성 순서

생성기 `Gen4`(`krpersona/generate/generator.py`)는 기본 생성기 `Gen0`(`krpersona/generate/base.py`)을 상속한다. `Gen0`은 센서스 값, 규칙, 임시 성격 모수로 한국 속성을 생성하고 조사 블록 속성 61개와 정신건강·소득 계층 속성은 MatrAIx 확률로 채운다. 이 기본 생성기를 직접 사용하는 곳은 MatrAIx 금지 규칙의 사전 분류(7.7절)다. 실제 페르소나 생성은 `Gen4`가 담당하며, 센서스 기본 집단(`Base`, 5.6절), 값 기록 함수 `_set`, `_alloc`, 기본 금지 규칙 `_extra_masks`를 재사용하고 `make`에서 각 조사 모형을 적용한다. 최종 출력에 임시 값으로 남는 속성은 없다(`PH = []`).

### 한국 속성 집합 $`K`$

| 구성 | 개수 | 정의 |
|---|---|---|
| `assign.build()`의 $`K_0`$ | 151 | 센서스 21, 규칙 17, 성격 52, 조사 블록 61(4.2절) |
| Schwartz 가치 | 10 | `schwartz_value_*` |
| 가치 문항 | 20 | `blocks/values.py`의 `VAL_STAR` |
| 추가 배정 속성 `KR_ADDED` | 40 | `english_proficiency`, `lang_english`, `dev_professional_status`, 성격 점수에서 파생한 37개(7.4절) |
| 합계 | 221 | 모두 MatrAIx 출력 속성 |

그래프의 나머지 노드 1,087개(출력 속성 1,069개, 잠재 노드 18개)는 `KRSampler.sample_rest`가 MatrAIx 순서로 추출한다(7.2절). 새 한국 속성 21개(`kr_*`)는 MatrAIx 그래프에 노드가 없으므로 출력에만 있고 MatrAIx 코드를 갖지 않는다. 따라서 어떤 MatrAIx 속성의 조건으로도 사용되지 않는다.

### 값을 기록하는 방법

- `_set(t, out)`: 값을 그대로 정한다. 조건용 코드는 `KRSampler.code_of`로 구하며, MatrAIx 범주가 아닌 값(예: `primary_language` = Korean, `lstyle_commute_mode` = Other)은 "범주 없음" 코드가 된다(7.2절).
- `_alloc(t, sets, out_custom)`: 행 $`i`$마다 허용 범주 집합 $`A_i`$를 받아 그 안에서 MatrAIx 확률로 하나를 추출한다(`KRSampler.draw_korean`). 출력 값은 `out_custom`이 주어진 행에서는 그 값(예: Unpaid family worker, Office / clerical), 아니면 추출된 MatrAIx 범주다. 조건용 코드는 출력 값과 관계없이 추출된 MatrAIx 범주다. 빈 집합은 "범주 없음" 코드가 되고 출력은 `out_custom`(보통 Not applicable)이다.
- `_put(t, sets, out)`: 조사 블록에서 사용하는 `_alloc`이다.

221개 가운데 집합 안에서 추출하는 속성은 75개(센서스 10개, 규칙 3개인 경력, 직급, 생애단계, 사업체 규모, 개발자 여부, 건강 블록 6개, KGSS 블록의 MatrAIx 범주 속성 54개)이고, 나머지 146개는 `_set`으로 정한다. 집합의 원소가 하나이면 MatrAIx 확률과 관계없이 그 값이 된다. MatrAIx 확률과 MatrAIx 금지 규칙이 한국 속성에 영향을 주는 곳은 원소가 둘 이상인 집합뿐이다.

자녀, 경력, 직급, 생애단계는 조사 블록보다 먼저 생성한다. 경력 → 직급 → 생애단계 순서를 사용하므로 직급이 Retired일 때 `retired_seniority_retirement_lifestage` 규칙을 생애단계 배분에 적용할 수 있다.

난수는 두 생성기에서 나온다. `Gen4.rng = default_rng(seed)`는 센서스 추출과 모든 한국 블록에, `KRSampler.rng = default_rng(seed)`는 MatrAIx 확률로 추출하는 모든 값(집합 안 배분, `sample_rest`, 재추출)에 사용된다. 두 생성기는 같은 시드로 생성한 같은 난수열을 서로 다른 위치에서 소비한다. 결과는 재현되지만 엄밀히 독립인 난수열은 아니다. MatrAIx `PersonaForwardSampler`가 따로 만드는 생성기는 사용하지 않는다.

## 7.2 MatrAIx 그래프 샘플러 `KRSampler`

`krpersona/matraix/sampler.py`의 `KRSampler`는 MatrAIx의 샘플러를 한국 속성이 먼저 정해진 상황에 맞게 고친 것이다. MatrAIx 쪽 원본은 `persona/synthesis/sampler/sampler.py`의 `PersonaForwardSampler`이고, 방법 설명은 `persona/synthesis/docs/sampling-method.md`에 있다(MatrAIx 커밋 3633d8d). `KRSampler`는 생성자에서 `PersonaForwardSampler(graph_path, SamplingConfig(seed, emit_only=False))`를 생성하여 MatrAIx가 그래프 파일(`persona/synthesis/graph/full_dag.json`)에서 컴파일한 표를 그대로 가져온다. 가져오는 것은 노드별 범주와 기본 확률(`values`, `prior`, `logprior`), 쌍별 연결의 로그비 표(`in_edges`, `_compile_pairwise_edges`), 전체 조건부 확률표의 조회표(`full_cpts`, `_compile_full_cpts`), 금지 규칙(`masks`, `_compile_masks`), CPT가 대체하는 부모(`replaced_parents`)와 축소 계수(`gamma`, `_compile_node_shrinkage`), 위상 순서(`topological_order`)다. 노드마다 확률을 계산하고 추출하는 부분(MatrAIx의 `_compile_plan`과 `sample_indices`)은 사용하지 않고 다시 작성했다.

### MatrAIx의 추출식

MatrAIx는 위상 순서대로 노드 $`i`$를 추출한다. 값 $`v`$의 로그 확률(정규화 전)은 다음과 같다.

```math
\log\tilde q_i(v)=\log P^0_i(v)+\gamma_i\Big[\sum_{c\in C_i}w_c\,\ell_c\big(v\mid \mathbf x_{\mathrm{pa}(c)}\big)+\sum_{e\in E_i,\ s(e)\notin R_i}w_e\,\ell_e\big(v\mid x_{s(e)}\big)\Big]
```

```math
\ell_e(v\mid u)=\log\max\big(P_e(v\mid u),\epsilon\big)-\log P^0_i(v),\qquad \gamma_i=\frac{1}{\max\Big(1,\sqrt{\sum_{c\in C_i}w_c^2+\sum_{e\in E_i,\ s(e)\notin R_i}w_e^2}\Big)}
```

$`P^0_i`$는 노드의 기본 확률, $`E_i`$는 들어오는 쌍별 연결(그래프 전체 6,999개, 가중치 $`w_e`$ 0.04\~0.95), $`C_i`$는 노드를 대상으로 하는 전체 조건부 확률표(CPT, 그래프 전체 54개, 가중치 $`w_c`$ 0.1\~1.0), $`R_i`$는 `replace_pairwise_parent_edges`가 참인 CPT의 부모 집합(54개 모두 참)이다. $`\epsilon = 10^{-12}`$다. CPT 조회표에 없는 부모 조합은 로그비 0, 즉 기본 확률이다. 연결 표에 없는 출발 범주의 행도 대상의 기본 확률로 설정한다. 그다음 조건이 성립하는 금지 규칙 $`m`$의 배수 $`M_m(v)`$를 곱한다. 그래프의 금지 규칙 524개는 모두 금지 값의 배수가 0이고 그 밖의 값은 1이다(43개는 금지 값이 비어 있어 효과가 없다).

```math
p_i(v)\propto\exp\big(\log\tilde q_i(v)-\max_{v'}\log\tilde q_i(v')\big)\prod_{m:\ \mathrm{cond}_m(\mathbf x)}M_m(v)
```

값은 정규화하지 않은 누적합에 대한 역누적분포 추출로 추출한다. `sample_indices(n, fixed=...)`의 `fixed`는 노드 하나를 모든 행에서 같은 값 하나로 고정하는 기능이며, 행마다 다른 값, 범주에 없는 값, 고정한 노드로 들어오는 연결의 처리는 지원하지 않는다. 이 때문에 샘플러를 따로 생성했다.

### 연결의 처리

한국 속성은 모두 MatrAIx 노드보다 먼저 정해진다. MatrAIx 연결 6,999개는 출발 $`s`$와 도착 $`t`$가 $`K`$에 속하는지에 따라 네 가지로 처리된다($`K`$ 221개 기준).

| 연결 $`s\to t`$ | 개수 | 처리 |
|---|---|---|
| $`s\in R_t`$(CPT가 대체하는 부모) | 13 | 제외한다(MatrAIx와 같음). `age_bracket → demo_generation`, `primary_language → lang_*` 12개 |
| $`s\in K,\ t\in K`$ | 467 | `in_K[t]`에 저장한다. $`t`$를 집합 안에서 추출할 때(`draw_korean`)만 사용한다 |
| $`s\notin K,\ t\in K`$ | 373 | 방향을 뒤집어 `in_mod[s]`에 저장한다. $`s`$를 나중에 추출할 때 이미 정해진 $`x_t`$를 조건으로 사용한다 |
| $`t\notin K`$ | 6,146 | MatrAIx와 같이 `in_mod[t]`에 저장한다. 그중 3,356개는 출발이 한국 속성이다 |

뒤집은 연결 373개의 출발은 89개 노드다. 출력 속성 79개에서 225개, 잠재 노드 10개에서 148개가 나온다. 잠재 노드 가운데 `phase3_psychometric_profile_component`(68개)와 `phase3_values_worldview_profile_component`(51개)가 대부분이다. 도착은 한국 속성 159개이고, 많이 받는 속성은 `pref_stability_vs_change` 23개, `values_priority`, `health_stress_level`, `trait_resilience` 각 17개, `pref_novelty_vs_familiarity`, `health_mental_health`, `risk_tolerance` 각 16개다.

한국 속성이 아닌 노드 $`b`$의 식은 다음과 같다. 마지막 합이 뒤집은 연결이다.

```math
\log\tilde q_b(v)=\log P^0_b(v)+\gamma^{\mathrm{KR}}_b\Big[\sum_{c\in C_b}w_c\,\ell_c(v\mid\cdot)+\sum_{e:\,s\to b,\ s\notin R_b}w_e\,\ell_e(v\mid x_s)+\sum_{e:\,b\to a,\ a\in K}w_e\big(\log P_e(x_a\mid v)-\log P^0_a(x_a)\big)\Big]
```

마지막 합의 $`-\log P^0_a(x_a)`$는 $`v`$와 무관해 정규화에서 지워지므로, 뒤집은 연결 하나는 $`q_b(v)`$에 $`\big[P_e(x_a\mid v)\big]^{\gamma^{\mathrm{KR}}_b w_e}`$를 곱한다. 연결이 하나이고 $`\gamma^{\mathrm{KR}}_b w_e = 1`$이면 베이즈 정리 $`P(v\mid x_a)\propto P^0_b(v)P_e(x_a\mid v)`$와 같다. 코드는 같은 로그비 표 $`L_e`$를 전치하지 않고 참조하여 이 항을 계산한다.

축소 계수는 한국 속성이 아닌 노드에서 다시 계산한다. 뒤집은 연결의 가중치가 부모 쪽에 더해진다.

```math
\gamma^{\mathrm{KR}}_b=\frac{1}{\max\Big(1,\sqrt{\max\big(\sum_{c\in C_b}w_c^2+\sum_{e:\,s\to b,\ s\notin R_b}w_e^2+\sum_{e:\,b\to a,\ a\in K}w_e^2,\ 10^{-12}\big)}\Big)}
```

이 때문에 58개 노드의 γ가 바뀐다. 예를 들어 `phase3_psychometric_profile_component`는 1.0에서 0.269로, `phase3_values_worldview_profile_component`는 1.0에서 0.311로, `decision_style`은 0.587에서 0.489로 줄어든다. 한국 속성은 MatrAIx의 γ를 그대로 사용한다(0.356\~1.0). 이 값은 지금은 그 노드에 작용하지 않는 뒤집은 연결의 가중치까지 포함해 계산된 것이므로, 집합 안 배분에서 한국 속성 간의 연결과 CPT는 다시 계산했을 때보다 더 많이 축소된다.

### 범주 없음 코드

MatrAIx 범주가 아닌 한국 값은 코드 $`k_t`$(범주 수, 즉 마지막 범주 다음 번호)로 기록한다. 모든 연결 표에는 이 코드 자리에 0인 열을 덧붙여 두므로, 이 값을 출발로 하는 연결과, 이 값을 조건으로 참조하는 뒤집은 연결은 인수 1이다. 그 밖의 효과는 다음과 같다.

- CPT의 부모 가운데 하나라도 이 코드이면 CPT 전체가 0인 행(기본 확률)을 사용한다. 그 부모의 몫만 제외되는 것이 아니다.
- 고정 금지 규칙의 조건에는 맞지 않는다. 따라서 이 값을 조건으로 하는 금지 규칙은 작동하지 않는다.
- 컴파일한 규칙 마스크(7.7절)는 마지막 행이 모두 허용이라 작동하지 않는다.
- 언어 마스크는 이 코드를 영어 능력 없음, 평생 언어 수 상한 없음으로 처리하고, 비개발자 마스크는 개발자 여부가 이 코드인 행에만 작동한다(7.5절, 7.6절).

이 코드를 갖는 값은 `primary_language` = Korean(모든 사람), `lstyle_commute_mode`의 Other와 Not applicable, `domain`, `role_function`, `seniority`, `company_size`의 Not applicable, `dev_professional_status` = Not a developer다. 집합 안에서 추출하는 직접 정의 범주(직무의 Office / clerical 등, 사업체 규모 6구간, 고용 상태의 Unpaid family worker, KGSS 블록의 종교 범주 등)는 추출된 MatrAIx 범주의 코드를 갖는다.

### 전체 조건부 확률표

CPT 54개 가운데 33개는 대상이 MatrAIx 노드이고, 33개 모두 부모에 한국 속성이 하나 이상 있다. 이들은 MatrAIx와 같이 쓰되 부모 값이 한국 값이다. 나머지 21개는 대상이 한국 속성이며, 그 속성을 집합 안에서 추출할 때만 사용한다. 이때 아직 정해지지 않은 부모 $`M`$은 각 부모의 기본 확률로 평균을 산출한다. $`D`$는 이미 정해진 부모다.

```math
\bar\ell_c(v\mid\mathbf x_D)=\log\max\Big(\sum_{\mathbf u_M}P_c(v\mid\mathbf x_D,\mathbf u_M)\prod_{p\in M}P^0_p(u_p),\ 10^{-12}\Big)-\log P^0_t(v)
```

조회표에 없는 부모 조합은 $`P_c(v\mid\cdot)=P^0_t(v)`$로 들어간다. 평균은 조건부 분포가 아니라 주변 기본 확률로 산출한다. 예를 들어 `highest_education`의 CPT(부모 `age_bracket`, `socioeconomic_band`)와 `demo_employment_status`의 CPT(`age_bracket`, `region`, `socioeconomic_band`)는 소득 계층이 나중(`_income`)에 정해지므로 소득 계층을 평균 내고, `years_experience`의 CPT(`age_bracket`, `demo_employment_status`, `seniority`)는 직급 범주에 대해 기본 확률로 가중 평균을 산출한다. 대상이 한국 속성인 CPT 가운데 한국 속성이 아닌 부모가 있는 것은 `att_ai`(부모 `role_function`, `years_experience`, `tech_savviness`, 가중치 0.55) 하나다. `tech_savviness`는 늘 평균 내며, CPT는 뒤집지 않으므로(뒤집는 것은 쌍별 연결뿐이다) `att_ai`와 `tech_savviness` 사이의 관계는 양쪽 어디에도 반영되지 않는다. `english_proficiency`의 CPT(`primary_language`, `region`, `highest_education`)는 주 언어가 범주 없음 코드라 전체가 꺼진다.

대상이 MatrAIx 노드인 CPT에서 부모가 아직 추출되지 않았으면 그 CPT를 건너뛰도록 되어 있으나, MatrAIx 순서에서는 부모가 항상 먼저이므로 이 경우는 생기지 않는다.

### 금지 규칙의 적용

한 노드에 걸린 금지 규칙은 다음 순서로 곱한다.

1. 고정 금지 규칙(`masks[t]`): MatrAIx 금지 규칙(그래프 순서), 기본 금지 규칙 141개, 충돌 수정 금지 규칙 286개(7.7절). 조건 속성이 모두 이미 정해졌을 때만 적용하고, 하나라도 아직 정해지지 않았으면 건너뛴다. 조건이 성립하는 행에 배수(0 또는 1)를 곱한다.
2. 행별 금지 규칙(`dyn[t]`): 이미 정해진 값에서 행마다 배수를 계산하는 함수다. 언어 마스크 49개, 비개발자 마스크 83개, 컴파일한 규칙 마스크 순서다(7.5\~7.7절). 함수가 `None`을 반환하면 작동하지 않는다.

어떤 금지 규칙을 곱했을 때 한 행의 모든 값이 0이 되면, 그 행은 그 금지 규칙을 곱하기 직전의 확률로 복원한다(`_logits`). 즉 그 행에서는 그 금지 규칙 하나만 무시되고 앞서 곱한 규칙은 유지된다. 따라서 금지 규칙이 서로 충돌하면 나중에 곱하는 규칙은 제외된다. 어떤 금지 규칙도 반드시 지켜진다고 보장되지 않는다.

```math
p^{(m)}_i(v)=\begin{cases}p^{(m-1)}_i(v)\,M_m(v) & \sum_{v'}p^{(m-1)}_i(v')M_m(v')>0\\ p^{(m-1)}_i(v) & \text{그 밖}\end{cases}
```

### 집합 안 배분 `draw_korean`

한국 속성 $`t`$를 행별 허용 집합 $`A_i`$ 안에서 추출할 때는 위 식에서 연결을 `in_K[t]`(이미 정해진 한국 속성에서 오는 것만), CPT를 위의 평균을 산출한 항으로 변경하고, 조건이 이미 정해진 금지 규칙을 적용한 $`p_t`$를 사용한다.

```math
P(x_t=v\mid A_i)=\begin{cases}\dfrac{p_t(v)\,\mathbf 1[v\in A_i]}{\sum_{v'\in A_i}p_t(v')} & \sum_{v'\in A_i}p_t(v')>0\\[2ex] \dfrac{P^0_t(v)\,\mathbf 1[v\in A_i]}{\sum_{v'\in A_i}P^0_t(v')} & \text{그 밖}\end{cases}
```

금지 규칙이 허용 집합의 값을 모두 지우면 허용 집합의 제약을 우선 적용한다. 이때는 기본 확률을 집합으로 제한해 사용하므로, 그 행에서는 금지 규칙뿐 아니라 이미 정해진 부모의 정보도 사용되지 않는다. 대상이 한국 속성인 금지 규칙은 이 경로에서만 작동한다. 생성자 인수 `placeholder`도 저장만 되고 사용되지 않는다.

### 나머지 노드 `sample_rest`

`sample_rest(codes)`는 한국 속성 221개의 코드를 받아, 나머지 노드 1,087개를 위상 순서대로 추출한다. 이미 정해진 노드 집합은 한국 속성 전부에서 시작해 한 노드를 추출할 때마다 늘어난다. 잠재 노드도 한국 값과 뒤집은 연결을 조건으로 추출되고, 그 값이 다시 출력 속성의 조건이 된다. 재추출(7.8절)은 같은 함수를 위반 행의 한국 코드만 전달하여 다시 호출한다.

## 7.3 규칙 속성과 센서스 속성의 세부 규칙

이 절은 4장에 없는 규칙의 세부 사항을 설명한다. 센서스 값을 MatrAIx 범주로 옮기는 대응표와 원소가 여럿인 집합(`{A, B}` 표기)은 `docs/tables/category_mapping.csv`에 있으며, 둘이 다르면 `generator.py`의 `make`가 기준이다. 아래 기호에서 나이는 센서스 만연령(85는 85세 이상), 출생 연도는 $`b = 2020 - \text{나이}`$다.

### 세대와 성장기 연대

`demo_generation`은 출생 연도로 정한다: $`b\le1945`$ Silent, 1946\~1964 Boomer, 1965\~1980 Gen X, 1981\~1996 Millennial, 1997 이후 Gen Z. 경계는 Pew Research Center의 세대 구분(Dimock, 2019, "Defining generations: Where Millennials end and Generation Z begins")과 같다(문헌. 코드에는 출처가 적혀 있지 않다). Gen Alpha는 생성하지 않는다. 센서스 나이가 85세에서 잘리므로 75세 이상은 모두 Silent다.

`lifex_formative_decade`는 10\~25세에 해당하는 연도 집합 $`Y=\{b+10,\dots,\min(b+25,\,2020)\}`$에서 각 연대에 속하는 연도 수에 비례해 하나를 추출한다.

```math
\Pr(d)=\frac{|Y\cap d|}{\sum_{d'}|Y\cap d'|},\qquad d\in\{1960\text{s-}70\text{s}\ (1960\text{–}1979),\ 1980\text{s},\ 1990\text{s},\ 2000\text{s},\ 2010\text{s},\ 2020\text{s}\ (2020\text{–}2029)\}
```

10\~25세 창은 가정이다. 1960년 이전 연도는 MatrAIx 범주가 없어 세지 않으므로, 1950년 이전 출생(70세 이상)은 모두 1960s-70s다. 겹치는 연도가 하나도 없으면 1960s-70s로 두도록 되어 있으나, 나이 상한이 85세라 이 경우는 생기지 않는다. 기준 연도가 2020년이므로 창은 2020년에서 잘리고, 19세(2001년생)는 2011\~2020년 가운데 2020년 한 해 때문에 1/10의 확률로 2020s가 된다.

### 자녀

자녀 속성 세 개는 한 사람의 자녀 나이 목록에서 계산한다(`_children`). 목록은 가구 명부에서 생성한 동거 자녀(5.6절의 `own`)에서 시작해 비동거 자녀를 더한다.

1. 센서스 출산 기록이 있는 사람(결혼 경험이 있는 여성, 그리고 5.6절에 따라 아내의 기록을 받은 가구주와 배우자 쌍의 기혼 남성): 비동거 자녀 수는 $`n_{nc}=\max(0,\ \text{출산아 수}-\text{사망 자녀 수}-\text{동거 자녀 수})`$다.
2. 기록이 없는 61세 이상 결혼 경험자(성별 무관): 고령화연구패널 10차 모형으로 생존 자녀 수 $`T`$를 동거 자녀 수 이상에서 추출하고 $`n_{nc}=\max(0,\ T-\text{동거 자녀 수})`$로 설정한다(`blocks/family.py`의 `draw_total`, 6장).
3. 그 밖의 사람(미혼, 기록이 없는 61세 미만 결혼 경험자): 비동거 자녀를 생성하지 않는다.

비동거 자녀의 나이는 61세 이상일 경우 고령화연구패널 모형의 묶음 평균값으로 결정한다. 같은 성과 연령대에 배정된 항목 중 비동거 자녀가 정확히 $`n_{nc}`$명인 항목을 평균 가중치에 비례해 추출하며, 해당 항목이 없으면 $`n_{nc}`$명 이상인 항목에서 $`n_{nc}`$개를 선택한다(`draw_gaps`). 나이 차이와 가중치는 응답자 5명 이상 묶음의 평균이며 구성 절차는 6.9절에 제시하였다. 61세 미만이거나 적절한 항목이 없으면 자녀마다 센서스 모자 나이 차이 빈도표(5.6절)에서 본인 나이 이하인 값을 독립 추출한다. 가구 명부에서 조부모로 분류되었으나 자녀가 없는 경우에는 본인 나이 − 15 이하의 나이 차이로 비동거 자녀 한 명을 추가한다. 해당 값이 없으면 25세의 나이 차이를 적용한다. 생성 경로는 내부 값 `kid_src`에 기록한다(0 센서스만, 1 고령화연구패널 나이 차이, 2 고령화연구패널 자녀 수).

| 속성 | 규칙($`n`$ 자녀 수, $`y`$ 막내 나이, $`c`$ 동거 자녀 있음, $`g`$ 조부모) |
|---|---|
| `demo_children_count` | $`n=0`$ None, $`y\ge20`$ Adult children, $`n=1`$ 1 child, $`n=2`$ 2 children, 그 밖 3+ children |
| `demo_parental_status` | $`g`$ Grandparent, $`n=0`$ Not a parent, $`y<1`$ New parent, $`y<18`$ Parent of minors, 그 밖 Parent of adults |
| `lifex_parenting_journey` | $`n=0`$ No children, $`y<13`$ Young children, $`y\le19`$ Teenagers, $`c`$ Grown children, 그 밖 Empty nester |

규칙은 위에서부터 처음 맞는 것을 사용한다. 경계값(성인 20세, 미성년 18세, 어린 자녀 13세, 청소년 19세 이하, 신생아 1세 미만)은 가정이다. Expecting, Step / foster parent, Raising grandchildren은 생성하지 않는다. 조부모 여부는 가구 명부에서만 판정하므로, 손자녀와 따로 사는 조부모는 Parent of adults가 된다. 비동거 자녀의 나이 차는 모두 15세 이상이므로, 거부 검사 "자녀와 나이 차 15세 미만"(7.8절)에 걸리는 것은 센서스 기반 가상 가구의 동거 자녀뿐이다.

### 경력, 직급, 생애단계

`years_experience`는 현 직업 근속 구간의 하한 $`\ell`$과 상한 $`u=\text{나이}-15`$(15세부터 일했다는 가정)에 겹치는 MatrAIx 구간을 허용 집합으로 두고 MatrAIx 확률로 추출한다. 구간은 0-2 [0, 2], 3-5 [3, 5], 6-10 [6, 10], 11-20 [11, 20], 20+ [20, 99]이고, 구간 $`[a, z]`$는 $`a\le u`$이고 $`z\ge\ell`$일 때 허용된다. 근속 코드의 하한은 1(6개월 미만), 2(6개월\~1년) 0년, 3(1\~3년) 1년, 4(3\~5년) 3년, 5(5\~10년) 5년, 6(10\~15년) 10년, 7(15\~20년) 15년, 8(20년 이상) 20년이다. 허용 구간이 없으면 0-2로 설정한다. 비취업자는 근속이 없으므로 $`\ell=0`$이고 나이로 허용되는 모든 구간에서 MatrAIx 확률이 선택한다. 즉 비취업자의 경력은 과거 경력으로 해석되며 자료로 정한 값이 아니다.

`seniority`는 다음 규칙을 위에서부터 적용한 집합 안에서 추출한다.

| 조건 | 허용 집합 |
|---|---|
| 비취업, 재학, 휴학 | Student / intern |
| 60세 이상 비취업, 또는 고용 상태 Retired | Retired |
| 취업, 직업 대분류 1(관리자) | Manager, Director, VP, C-suite |
| 취업, 고용원이 있는 자영업자 | Founder, Manager, C-suite |
| 취업, 고용원이 없는 자영업자 | Founder, Mid, Senior |
| 그 밖의 비취업 | 빈 집합 → Not applicable(범주 없음 코드) |
| 그 밖의 취업(임금근로자, 무급가족종사자) | 경력 0-2: Student / intern, Entry; 3-5: Entry, Mid; 6-10: Mid, Senior; 11-20: Mid, Senior, Lead / Principal; 20+: Senior, Lead / Principal |

홈메이커와 실업자에게는 현재 직급을 부여하지 않고 Not applicable을 사용한다.

`life_stage`는 다음 조건이 성립하는 값을 모두 모은 집합 $`\Omega`$ 안에서 추출한다. 여기서 취업은 고용 상태 코드가 Full-time, Part-time, Self-employed, Gig / freelance인 경우로, 무급가족종사자(코드 Self-employed)를 포함한다.

| 값 | 조건 |
|---|---|
| Student | 재학, 휴학 |
| Early career | 취업이고 35세 미만 |
| Parent of young kids | 막내가 13세 미만 |
| Mid-life | 40\~64세 |
| Career change | 취업 또는 Unemployed이고 25\~59세 |
| Empty nester | 막내가 20세 이상이고 동거 자녀 없음 |
| Retirement | 60세 이상 비취업, 또는 Retired |

$`\Omega`$가 비면 40세 미만은 Early career(경력이 20+이면 Mid-life), 40\~59세는 Mid-life, 60세 이상은 Retirement로 설정한다. 연령 경계는 모두 가정이다.

### 우세 성격

`dominant_trait`는 BFI-2 요인 점수 $`\mathbf z=(z_O,z_C,z_E,z_A,z_N)`$(7.4절)에서 정한다. $`z_{(1)}\ge z_{(2)}`$는 가장 큰 두 값이다.

```math
x_{\mathrm{dom}}=\begin{cases}\text{High }\arg\max_d z_d & z_{(1)}\ge0.51\ \text{그리고}\ z_{(1)}-z_{(2)}\ge\delta\\ \text{Balanced} & \text{그 밖}\end{cases}
```

0.51은 요인 범주의 High 경계와 같으므로, 우세 성격이 가리키는 요인은 항상 High 또는 Very high다. δ는 Balanced 비율을 MatrAIx 기본 확률 26%에 맞추는 값으로 실행마다 정한다(7.8절).

### 정신건강

`health_mental_health`는 건강 블록(6장)이 생성한 PHQ-9 합계와 GAD-7 합계, 주관적 건강에서 위부터 처음 맞는 규칙으로 정한다: PHQ-9 ≥ 20 또는 GAD-7 ≥ 15이면 In crisis, PHQ-9 ≥ 10 또는 GAD-7 ≥ 10이면 Struggling, PHQ-9 ≥ 5 또는 GAD-7 ≥ 5이면 Stable, 주관적 건강이 매우 좋음 또는 좋음이면 Thriving, 그 밖은 Stable. 경계 5, 10, 15, 20은 두 척도의 표준 절단점(Kroenke 외, 2001; Spitzer 외, 2006)이고, 네 범주와의 대응은 가정이다.

### 주거

`demo_housing_status`는 가구주의 자녀(관계 3)이면 Living with family, 점유형태가 자기 집이면 가계금융복지조사의 주택담보대출 모형(6장)으로 Mortgage와 Own outright를 나누고, 전세, 월세, 사글세, 무상은 모두 Renting이다.

### MatrAIx 확률이 실제로 값을 정하는 곳

집합 안 배분에서는 한국 자료가 집합을, MatrAIx 확률이 집합 안의 선택을 정한다. 집합의 원소가 여럿인 경우는 미혼의 {Single, In a relationship, Engaged}, 박사 졸업의 {Doctorate, Postdoc}, 자영업의 {Self-employed, Gig / freelance}, 60세 미만 비취업자(재학, 휴학자와 결혼 전 취업이 없는 결혼 경험 여성 제외)의 {Unemployed, Homemaker}, 60세 이상 경력 단절 여성의 {Homemaker, Retired}, 산업 J, M, S의 분야, 직업 대분류 2와 3의 직무, 시각, 청각, 이동의 정상 쪽과 제약 쪽 두 범주, 운전 상태, 경력, 직급, 생애단계, 동거, 약혼 중인 사람의 관계 기간, 그리고 KGSS 블록에서 한 범주가 MatrAIx 범주 여럿에 대응하는 속성이다. 특히 60세 미만 비취업 남성의 Unemployed와 Homemaker는 센서스에 구직 여부가 없어 MatrAIx 확률에 따라 결정한다.

## 7.4 성격 점수에서 파생한 MatrAIx 속성

### 성격 측정 단계

성격 모형의 모수(성별과 연령 효과 $`B`$, 요인 상관 $`\Phi`$)의 추정은 6장에서 다룬다. 생성기 `_personality`는 이 모수로 요인 점수를 생성하고 속성 범주로 변경한다. 요인 순서는 O, C, E, A, N이다.

```math
\boldsymbol\eta_i=\boldsymbol\phi(\text{성}_i,\text{나이}_i)B+L\boldsymbol\varepsilon_i,\quad LL^\top=\Phi;\qquad z_f=\lambda_f\,\eta_{d(f)}+\sqrt{1-\lambda_f^2}\,u_f
```

| 단계 | 식과 상수 | 근거 |
|---|---|---|
| BFI-2 측면 15개 | $`\lambda_f`$ = `LAM_BFI2`(0.54\~0.90) | 한국판 BFI-2 측면 수준 ESEM, 직장인 표본 $`n=856`$, Choi 외(2025), *Assessment*, 표 3(문헌) |
| BFI-2 요인 5개 | $`z_d=\bar z_{f\in d}/\mathrm{sd}_d`$, $`\mathrm{sd}_d=\sqrt{(\sum_f\lambda_f)^2+\sum_f(1-\lambda_f^2)}\,/\,3`$ | 세 측면 평균의 표준편차로 나눈 것 |
| IPIP-NEO 측면 30개 | $`\lambda_g`$ = `LAM_IPIP`(0.32\~0.91) | 한국판 IPIP-NEO-300 성인 $`N=334`$, 측면 점수 5요인 탐색적 요인분석의 자기 요인 부하량, 장승민(2017) 연구보고서 표 7(문헌) |
| 같은 측면의 공유 | BFI-2와 IPIP-NEO가 같은 측면을 측정하는 15쌍(`SAME_FACET`)은 고유 성분을 $`u'_g=\rho u_b+\sqrt{1-\rho^2}\,u`$로 공유. $`\rho=\mathrm{clip}\big((r^\ast-\lambda_b\lambda_g)/\sqrt{(1-\lambda_b^2)(1-\lambda_g^2)},0,1\big)`$, $`r^\ast=0.6`$ | 가정. 공유하지 않으면 두 측정의 상관이 요인 경로뿐이라 예컨대 자기주장성은 $`0.55\times0.58=0.32`$가 된다 |
| 범주 | `level(z)`: 경계 −1.51, −0.51, 0.51, 1.51 → Very low\~Very high | MatrAIx 기본 확률 0.065, 0.24, 0.39, 0.24, 0.065를 표준정규 경계로 옮겨 반올림 |
| 같은 측면의 정반대 극단 | BFI-2가 Very high인데 IPIP가 Very low이면 IPIP를 Low로, BFI-2가 Very low인데 IPIP가 Very high이면 High로 바꿈. 점수 $`z`$는 그대로 | 사전 검토에 따른 일관성 제약(규칙 묶음 2, 3) |
| MBTI 네 글자 | $`z_k=0.7\,\eta_{j(k)}+\sqrt{0.51}\,\varepsilon`$, E←$`\eta_E`$, N←$`\eta_O`$, F←$`\eta_A`$, J←$`\eta_C`$, 글자는 $`z_k>0`$. BFI-2 외향성이 Very high이거나 사교 에너지가 Strong extrovert이면 E, Very low이거나 Strong introvert이면 I | 부하량 0.7은 가정. 경계 0은 MatrAIx의 16유형 균등 분포 |
| 사교 에너지 | $`z=0.7\,\eta_E+\sqrt{0.51}\,\varepsilon`$, MatrAIx 기본 확률의 누적값을 표준정규 경계로 써서 Strong introvert\~Strong extrovert. 외향성 Very high이면 Introvert 이상, Very low이면 Extrovert 이하, 우세 성격이 High extraversion이면 Ambivert 이상 | 부하량 가정과 일관성 제약 |

### 파생 속성 37개

MatrAIx에는 성격 요인과 같은 개념이거나 가까운 개념의 속성(호기심, 규율, 친절, 계획 선호 등)이 따로 있고, MatrAIx 그래프에서는 이들이 성격 요인과 약하게만 연결되어 있다. 이 가운데 37개(`generator.py`의 `DERIVED`)는 한국 속성 집합 $`K`$에 포함하여 한국 성격 점수에서 생성한다. 속성 $`t`$마다 원 점수 $`s`$, 방향 $`\sigma\in\{+1,-1\}`$, 상관 $`r`$, 기준 속성(anchor) 목록이 있다.

```math
z_t=\sigma\,r\,x_s+\sqrt{1-r^2}\,\varepsilon,\qquad c_t=\#\Big\{k\in\{0,\dots,K_t-2\}:\ \Phi^{-1}\Big(\sum_{j\le k}p_j\Big)<-z_t\Big\}
```

$`x_s`$는 원 점수의 연속값(BFI-2 측면과 요인 점수, IPIP-NEO 측면 점수, MBTI J, F 글자의 잠재 점수 $`z_J`$, $`z_F`$)이고, $`p_j`$는 MatrAIx 기본 확률을 MatrAIx 범주 순서대로 놓은 것이다. 37개 모두 첫 범주가 속성 이름의 앞쪽 극(예: Signature, Very high, Highly planned, Craves routine)이며, $`z_t`$가 클수록 앞쪽 범주가 된다($`c_t=0`$이 첫 범주). $`x_s`$의 분산이 1이면 범주 비율은 MatrAIx 기본 확률과 같다. $`r`$은 0.8(거의 같은 개념) 21개, 0.7(관련 개념) 11개, 0.6 5개이며 모두 가정이다.

기준 속성 $`(a, s_a)`$는 정반대 극단을 막는다. $`s_a=+1`$이면 $`a`$가 첫 범주일 때 $`t`$는 마지막 범주가 될 수 없고($`c_t\le K_t-2`$), $`a`$가 마지막 범주일 때 $`t`$는 첫 범주가 될 수 없다($`c_t\ge1`$). $`s_a=-1`$이면 반대다. MBTI 기준(`MBTI_J`, `MBTI_F`)은 글자 J(F)를 첫 범주, P(T)를 마지막 범주로 보므로, 모든 행에 제약이 적용된다. 예를 들어 J인 사람은 `pref_plan_vs_spontaneous`가 Highly spontaneous가 될 수 없고 P인 사람은 Highly planned가 될 수 없다.

MBTI의 F를 직관 쪽(`pref_logic_vs_intuition`의 Intuition-leaning)에 대응시킨 것도 근사다.

## 7.5 다중언어와 언어 능력

### 한국어와 영어

한국어는 규칙으로 정한다: `lang_korean` = Native, `primary_language` = Korean(7.3절). Korean은 MatrAIx의 주 언어 12개 범주에 없으므로 범주 없음 코드가 된다. 그 결과 주 언어를 부모로 하는 CPT 13개(`english_proficiency`, `lang_english`, 그리고 `lang_mandarin`, `lang_spanish`, `lang_hindi`, `lang_arabic`, `lang_french`, `lang_portuguese`, `lang_bengali`, `lang_russian`, `lang_japanese`, `lang_german`, `lang_swahili`)는 모두 꺼진다. 이 CPT들이 `primary_language → lang_*` 쌍별 연결을 대체하고 있었으므로, 이 11개 외국어는 주 언어와의 관계를 전혀 받지 않는다. 주 언어를 조건으로 하는 MatrAIx 금지 규칙 49개(대상이 언어 속성인 것 48개, `english_proficiency`인 것 1개)도 작동하지 않는다.

영어 능력 `english_proficiency`는 KGSS 블록의 2018년 영어 문항 모형(6장)으로 정한다. 범주는 Fluent (C1-C2), Intermediate (B1-B2), Basic (A1-A2), None 네 개이고 Native는 생성하지 않는다. KGSS 범주 하나가 MatrAIx 범주 하나에 대응하므로 집합 안 배분은 값을 변경하지 않는다. `lang_english`는 같은 능력을 다른 범주로 적은 속성이므로 `_set`으로 그대로 옮긴다(`EN_LANG`).

| `english_proficiency` | Native | Fluent (C1-C2) | Intermediate (B1-B2) | Basic (A1-A2) | None |
|---|---|---|---|---|---|
| `lang_english` | Native | Fluent | Conversational | Basic | None |

`lang_english`는 `_set`으로 직접 정하므로 두 영어 속성의 수준을 맞추는 금지 규칙 5개와 `lang_english`를 대상으로 하는 다른 금지 규칙은 작동하지 않는다. 영어 능력과 한국어에서 나가는 MatrAIx 연결은 사용한다. `lang_english`와 `lang_korean`으로 들어오는 연결(`lifex_languages_lifetime`, `phase3_language_profile_component`에서)은 방향을 뒤집어, 이 두 노드를 추출할 때 영어와 한국어 값을 조건으로 사용한다.

### 다른 언어를 제한하는 금지 규칙

외국어 48개(`lang_*` 가운데 `lang_korean`, `lang_english` 제외)와 언어 관련 MatrAIx 속성에는 다음 금지 규칙이 적용된다. MatrAIx 위상 순서에서 `multilingualism`(23번째, 부모 없음)이 가장 먼저, `lifex_languages_lifetime`(69번째), 외국어(237\~377번째), `demo_home_language`(379번째) 순서로 추출된다.

| 출처 | 조건 → 금지 |
|---|---|
| 기본 금지 규칙 | `region` = East Asia → 외국어 48개와 `english_proficiency`의 Native, 그리고 다른 나라 문화 39개의 Native |
| 충돌 수정 | 영어 Intermediate 또는 Fluent → `multilingualism` Monolingual, `lifex_languages_lifetime` One |
| 충돌 수정 | `lifex_immigration_generation` Native multi-generational → `demo_home_language` Heritage language |
| MatrAIx | `multilingualism` Monolingual → 평생 언어 수 Two 이상, Bilingual → One, Trilingual+ → One, Two(약한 규칙 3개) |
| MatrAIx | `multilingualism`만 조건인 언어 예산 규칙 114개(소수 언어 38개 × 3): Monolingual, Bilingual → 그 언어의 Conversational 이상, Trilingual+ → Fluent, Native |
| 언어 마스크(행별) | 아래 식 |

MatrAIx의 언어 예산 규칙은 주요 언어 12개(영어 포함)에 대해서는 주 언어가 다른 주요 언어일 것을 조건으로 하므로(36개) 한국인에게는 작동하지 않고, 나머지 소수 언어 38개에 대해서는 `multilingualism`만 조건으로 하므로(114개) 작동한다. 따라서 소수 언어는 처음 추출된 `multilingualism`이 Trilingual+일 때만 Conversational이 될 수 있고(Fluent와 Native는 늘 금지), 주요 외국어 11개는 `multilingualism`과 관계없이 아래 언어 마스크로만 수가 제한된다.

`dyn_language_masks`는 외국어 $`t`$를 추출할 때, 평생 언어 수가 이미 정해졌으면 지금까지 Conversational 이상인 언어 수가 평생 언어 수 상한에 이른 행에서 $`t`$의 Conversational, Fluent, Native를 금지한다.

```math
n_i(t)=1+\mathbf 1[\text{영어}_i\in\{\text{Native, Fluent, Intermediate}\}]+\sum_{x\ne t,\ x\ \text{이미 추출됨}}\mathbf 1[x_i\in\{\text{Conversational, Fluent, Native}\}],\qquad n_i(t)\ge\mathrm{cap}(\text{평생}_i)\ \Rightarrow\ M_t(v)=0\ \ (v\ge\text{Conversational})
```

상한은 One 1, Two 2, Three 3이고, Four+, Polyglot, 범주 없음은 상한이 없다(99). 앞의 1은 한국어다. `demo_home_language`는 영어(Intermediate 이상)와 이미 추출된 외국어 가운데 Conversational 이상인 것이 하나도 없으면 Same as primary만 허용한다. 집에서 한국어가 아닌 말을 쓰려면 그 말을 할 수 있어야 한다는 규칙이다. 이 마스크는 이미 정해진 언어만 집계하는데, 외국어가 모두 집 언어보다 먼저 추출되므로 실제로는 외국어 전부를 집계한다.

### 다중언어 `_multi`

`multilingualism`은 MatrAIx 그래프에서 부모가 없는 노드라, 그대로 두면 기본 확률(Monolingual 0.42, Bilingual 0.43, Trilingual+ 0.15)에서 영어 규칙만 반영해 추출된다. `sample_rest`가 끝난 뒤 실제로 할 수 있는 언어 수로 이 값을 다시 정한다(재추출 때마다도 다시 정한다).

```math
n_i=1+\mathbf 1[\text{영어}_i\in\{\text{Native, Fluent, Intermediate}\}]+\sum_{t\in\text{외국어}}\mathbf 1[x_{it}\in\{\text{Conversational, Fluent, Native}\}],\qquad \text{multilingualism}_i=\begin{cases}\text{Monolingual}&n_i=1\\ \text{Bilingual}&n_i=2\\ \text{Trilingual+}&n_i\ge3\end{cases}
```

출력된 `multilingualism`은 언어 속성과 항상 맞는다. 그러나 덮어쓰기 전의 값이 이미 다른 값을 정하는 데 쓰였다. `multilingualism`의 MatrAIx 자식 6개(`register`, `cog_use_of_jargon`, `cog_precision_of_language`, `cog_formality`, `tone_expected`, `modality_pref`), 평생 언어 수에 걸린 MatrAIx 규칙 3개, 소수 언어의 예산 규칙 114개는 모두 덮어쓰기 전 값으로 계산되었다. 또 언어 마스크는 위쪽 상한만 걸고 아래쪽은 제한하지 않으므로, 평생 언어 수가 Two 이상인데 최종 값이 Monolingual인 사람이 생길 수 있다. 결과 분포는 최종 표본 `out_on`에서 Monolingual 35.5%, Bilingual 15.2%, Trilingual+ 49.3%이고, 영어 외 외국어를 하나 이상 Conversational 이상으로 하는 사람이 61.1%, 10개 이상인 사람이 8.6%이다.

사전 검토에서 언어 수 규칙을 두 속성 간의 금지 조건으로 바꾸면 특정 외국어를 강제할 수 있음을 확인했다. 따라서 언어 속성(`lang_*`, `multilingualism`, `lifex_languages_lifetime`, `demo_home_language`, `primary_language`, `english_proficiency`)이 들어간 쌍은 컴파일하지 않고, 언어 수는 위의 언어 마스크와 `_multi`로 다룬다(8.5절, 8.7절).

## 7.6 개발자가 아닌 사람

### 개발자 여부

`_dev`는 직업 대분류 2(전문가 및 관련 종사자)인 취업자에게만 지역별고용조사 2025년 상반기 B형의 3자리 직업 모형(`blocks/dev.py`, 6장)을 적용한다. 분류 1은 Professional developer(한국표준직업분류 222 컴퓨터 시스템 및 소프트웨어 전문가, 223 네트워크 및 정보 보안 전문가, 224 데이터 전문가), 2는 Non-developer technologist(221 컴퓨터 하드웨어 및 통신공학 전문가, 225 정보 시스템 및 웹 운영자), 0은 그 밖의 전문가다. 분류 0인 사람과 대분류 2가 아닌 모든 사람(비취업자 포함)은 `dev_professional_status`가 Not a developer다. Not a developer는 MatrAIx 범주가 아니므로 범주 없음 코드가 되고, 이 사람들의 비개발자 표시(`nondev`)가 참이 된다. MatrAIx 범주 Learning to code, Hobbyist / side-project coder, Student developer, Former / inactive developer는 자료가 없어 생성하지 않는다. MatrAIx의 기본 확률에서는 Former / inactive developer가 0.70이다.

개발자 여부로 들어오던 MatrAIx 연결 9개(`skill_coding`, `tool_git`, `tool_github`, `tool_python`, `tool_vs_code`, `tool_github_copilot`, `tool_docker`, `tool_sql`, `tech_savviness`에서)는 뒤집혀, Professional developer와 Non-developer technologist는 이 속성들이 그 값에 맞는 쪽으로 기울어 추출되고 비개발자는 범주 없음 코드라 인수 1이다. 충돌 수정 금지 규칙은 Professional developer에게 `skill_coding`의 None, Beginner, `tech_savviness`의 Avoidant, `open_source_activity_level`의 No coding activity를 금지한다.

### 비개발자의 개발 속성

`masks.py`의 `nondev_plan`은 개발 관련 속성을 두 종류로 분류한다. 전체 목록은 `docs/tables/nondev_attributes.csv`(133행)에 있다. 이 표에는 값 None이 문자열로 들어 있으므로 pandas로 불러올 때 `keep_default_na=False`를 줘야 한다.

| 종류 | 개수 | 비개발자의 값 | 방법 |
|---|---|---|---|
| 값을 정하는 속성 | 83 | `NONDEV_VALUE` 15개(예: `skill_coding` None, `open_source_activity_level` No coding activity, `coding_ai_usage_frequency` Never used, `github_contribution_mode` Rare GitHub user), `prog_*` 33개 None, `ai_task_*` 12개 Not applicable, 개발 도구 `DEV_TOOLS` 23개 Never used | 비개발자 마스크가 그 값만 허용(MatrAIx 범주이므로 조건 코드도 그 값) |
| 출력만 바꾸는 속성 | 50 | Not applicable | MatrAIx 확률로 평소대로 추출하고, 출력할 때 비개발자의 값만 Not applicable로 바꿈 |

출력만 바꾸는 50개는 `dimensions.json`의 분류가 `Developer:`로 시작하거나 `Skills: Programming`인 속성에서 개발자 여부와 값을 정하는 속성을 뺀 것이다(Skills: Programming 11, Developer: Code Maintenance 9, Agent Adoption 9, Technology Evaluation 8, AI Adoption 6, Professional Context 4, Community Behavior 2, Open Source Behavior 1). 이 속성들의 범주 목록은 MatrAIx 범주에 Not applicable을 더한 것이다. 숨은 MatrAIx 값은 그 자손의 조건으로 쓰이지만 어디에도 저장되지 않는다.

비개발자 마스크는 행별 금지 규칙이므로 고정 금지 규칙 다음에 곱해진다. 앞선 고정 금지 규칙이 정해진 값을 이미 금지했으면 그 행은 모든 값이 0이 되어 비개발자 마스크가 무시된다(7.2절). 예를 들어 MatrAIx 금지 규칙 `v3_mask_domain_support_skill_coding_Software_and_AI`(분야 Software & AI이면 `skill_coding` None 금지)가 먼저 작동하므로, 정보통신업(산업 J)에서 일하는 사무직처럼 분야가 Software & AI인 비개발자는 코딩 능력이 None이 아니게 된다. 이런 사람의 수는 최종 표본 `out_on`에서 167명(Beginner 100명, Intermediate 67명, 모두 분야 Software & AI)다. Professional developer와 Non-developer technologist는 개발 속성을 모두 MatrAIx 확률로 받는다.

## 7.7 금지 규칙(마스크)

생성 중에 확률에 0을 곱하는 금지 규칙은 일곱 종류다. 적용 순서와 되돌림 규칙은 7.2절에 있다. 규칙 묶음에서 금지 규칙을 생성한 과정은 8장에서 다루고, 여기서는 생성기가 금지 규칙을 불러와 적용하는 방식만 설명한다.

| 종류 | 개수 | 코드 | 형태 |
|---|---|---|---|
| MatrAIx 금지 규칙, 대상이 MatrAIx 노드 | 411(금지 값이 있는 것 370) | 그래프 `conditional_masks` | 고정 |
| MatrAIx 금지 규칙, 대상이 한국 속성 | 113(금지 값이 있는 것 111) | 같음 | 고정, 집합 안 배분에서만 |
| 기본 금지 규칙 | 141 | `generate/base.py`의 `Gen0._extra_masks` | 고정 |
| 충돌 수정 금지 규칙 | 286 | `generate/masks.py`의 `conflict_masks` | 고정 |
| 언어 마스크 | 49 | `dyn_language_masks` | 행별 |
| 비개발자 마스크 | 83 | `nondev_masks` | 행별 |
| 컴파일한 규칙 마스크 | 929쌍 | `rule_pair_masks`가 `artifacts/masks/rule_masks.pkl`을 불러옴 | 행별 |

기본 금지 규칙과 충돌 수정 금지 규칙 427개는 `docs/tables/masks_static.csv`에, MatrAIx 금지 규칙 가운데 대상이 한국 속성인 것의 분류는 `docs/tables/matraix_masks.csv`에, 컴파일한 규칙 마스크의 금지 칸은 `docs/tables/masks_compiled.csv`에 있다. KGSS 블록 안에서 KGSS 속성 간, 또는 KGSS 속성과 성격 속성 사이에 적용하는 금지 쌍(`blocks/kgss.py`의 `KPAIRS`, 예: `big5_sympathy`가 Very high이면 `trait_empathy` Absent 금지)은 KGSS 모형의 추출 단계에 속하므로 6장에서 다룬다.

### 대상이 한국 속성인 MatrAIx 금지 규칙

한국 속성을 대상으로 하는 규칙은 개별 검토가 아닌 예비 생성 결과를 기준으로 유지 여부를 분류한다. `matraix/classify_masks.py`는 기본 생성기 `Gen0`(`syn_s1`, 시드 11, 스위치 켬)으로 60,000명을 거부 없이 생성하고, 금지 값이 있는 규칙 103개(기본 속성 집합 $`K_0`$가 대상인 것)마다 출력 값이 규칙을 어긴 사람 수 $`h_m`$을 집계한다(`own_masks.mask_hits`: 대상의 출력 값이 금지 값이고 조건 속성의 출력 값이 모두 허용 목록에 있음). $`h_m>0`$이면 폐기, $`h_m=0`$이면 모순 검사로 유지한다. 결과는 유지 84개, 폐기 19개이고 `artifacts/masks/mask_class.pkl`에 저장된다. 이 분류는 다음과 같은 한계가 있다.

- 의미가 아니라 한 번의 표본에서 위반이 있었는지로 나눈 것이다. 유지한 규칙에는 MatrAIx가 약한 규칙(soft)으로 분류한 것이 있고, 폐기한 규칙에는 강한 규칙(hard)이 있다.
- 기본 생성기(임시 성격 모수, 조사 블록 대신 MatrAIx 확률)의 예비 표본으로 분류했으며 실제 생성기 `Gen4`로 재분류하지 않았다. 따라서 현재 모형에서의 타당성을 보장하지 않는다.
- 유지한 84개 가운데 39개는 조건이 미성년 연령대(Under 5, 5-12, 13-17)뿐이라 19세 이상 인구에서는 걸릴 일이 없다.
- 현재 $`K`$에 포함되지만 사전 분류 대상에서 빠진 8개(`lang_english` 4, `dev_professional_status` 3, `english_proficiency` 1)는 분류되지 않았고 모순 검사에도 없다.

분류는 거부 검사에만 영향을 미친다. 생성 중에는 유지 또는 폐기와 관계없이 다음과 같이 작동한다.

| 생성 중 작동 | 유지 | 폐기 | 미분류 | 합계 |
|---|---|---|---|---|
| 집합 안 배분에서 작동(조건이 먼저 정해짐) | 69 | 10 | 3 | 82 |
| 조건이 대상보다 늦게 정해져 작동하지 않음 | 1 | 4 | 1 | 6 |
| 대상을 `_set`으로 정해 작동하지 않음 | 14 | 5 | 4 | 23 |

조건이 늦게 정해지는 6개는 소득 계층을 조건으로 학력을 제한하는 `persona8b_ses_low_education`과 `v4_2_soft_adult_high_income_low_education`(소득 계층은 `_income`에서 학력보다 나중에 정해짐), 분야를 조건으로 학력을 제한하는 `v4_2_soft_adult_stem_low_education`과 `v4_2_soft_adult_law_low_education`(분야는 학력보다 나중), 그리고 조건이 MatrAIx 속성인 `history_limited_marital_status`와 `v4_4_final_skill_none_no_professional_developer`다. 폐기한 규칙도 집합 안 배분에서는 작동한다. 예를 들어 `persona8b_age_lifestage_2534`(25\~34세는 Student, Empty nester, Retirement 금지)는 생애단계 배분에서 그 값들을 지우고, 허용 집합이 모두 지워지면 허용 집합의 제약을 우선 적용한다(7.2절). 폐기 규칙에서 위반이 나온 것은 이 경로 때문이다.

### 기본 금지 규칙 141개

`Gen0._extra_masks`는 센서스 값과 MatrAIx 속성이 어긋나지 않게 하려고 적용하는 기본 금지 규칙이다. `region` = East Asia이면 다른 나라 문화 39개(`cult_*`, `cult_south_korea` 제외)와 다른 언어 49개(`lang_*`, `lang_korean` 제외, `lang_english` 포함), `english_proficiency`의 Native를 금지한다(89개). `lifex_geographic_mobility` = Never left hometown이면 다른 나라 문화의 Lived there를 금지한다(39개). 영어 두 속성을 같은 수준으로 맞추는 규칙 5개, 혼인 상태와 연애 이력 2개, 사별과 상실 경험 1개, 학력과 학업 경로 1개, 취업 여부와 근무 일정 2개, 종교와 신앙 이력 2개가 나머지다. 대상이 한국 속성인 9개 가운데 `lang_english`의 6개는 작동하지 않고, `english_proficiency`의 1개와 `lifex_faith_journey`의 2개는 집합 안 배분에서 작동한다. 종교와 신앙 이력은 모두 KGSS 블록 속성이며, 종교를 먼저 추출하므로 두 규칙이 작동한다.

### 충돌 수정 금지 규칙 286개

### 행별 금지 규칙

언어 마스크와 비개발자 마스크는 7.5절과 7.6절에 있다. 컴파일한 규칙 마스크는 `rule_masks.pkl`의 항목 $`(t, c)\mapsto F`$로 저장된다. $`F`$는 $`(k_c+1)\times k_t`$ 불리언 행렬로, $`F[j, v]`$가 참이면 조건 속성 $`c`$가 $`j`$번째 범주일 때 대상 $`t`$의 $`v`$를 금지한다. 마지막 행은 범주 없음 코드용이며 모두 거짓(허용)이다. `rule_pair_masks`는 대상이 한국 속성인 항목을 버리고, 나머지마다 "조건 속성이 이미 정해졌으면 $`1-F[\min(x_c, k_c)]`$를 배수로, 아니면 작동하지 않음"인 함수를 생성한다. 따라서 조건이 대상보다 늦게 추출되는 항목은 작동하지 않는다. 파일이 없으면 이 마스크는 없다. 저장된 행렬에는 어느 규칙에서 나온 칸인지가 기록되지 않는다. 작동하는 항목 수와 금지 칸 수는 929쌍, 금지 칸 2,155개 가운데 554쌍, 1,322칸이다(조건이 한국 속성인 쌍 179개 포함)이다.

## 7.8 거부, 재추출, 보정

`generate/run.py`는 예비 생성 두 번으로 δ와 칸별 통과율을 정한 뒤, 묶음 단위로 생성하고 거부 검사를 통과한 사람만 남긴다. 고정 규칙 위반의 재추출은 `make` 안에서 거부 검사 전에 한다.

### 우세 성격 기준 δ

첫 번째 예비 생성은 재추출을 끈 채(`repair_on = False`) $`B`$명(기본 50,000명, 다섯 번째 인수)을 생성하고 BFI-2 요인 점수 $`\mathbf z`$를 저장한다. Balanced 비율

```math
\widehat{\Pr}(\text{Balanced};\delta)=\frac1B\sum_{i=1}^{B}\mathbf 1\big[\neg\big(z_{i(1)}\ge0.51\ \wedge\ z_{i(1)}-z_{i(2)}\ge\delta\big)\big]
```

이 26%가 되는 δ를 $`[0, 2]`$에서 이분법 40회로 찾고(중점의 비율이 0.26보다 작으면 아래 끝을 올린다), 소수 넷째 자리로 반올림한다. 26%는 MatrAIx의 `dominant_trait` 기본 확률이다. δ는 거부 전 예비 표본에서 한 번만 정하며, 거부 후 비율과 함께 반복 보정하지 않는다. 통과율이 1에 가까우면 차이는 작다. 나머지 다섯 범주(High openness 등, MatrAIx 기본 확률 0.135, 0.17, 0.135, 0.165, 0.135)는 맞추지 않고 성격 모형이 결정한 값을 유지한다. 표본별 δ는 0.1254(`val_on`), 0.1254(`val_novl`), 0.1302(`out_on`), 0.1305(`out_off`)이고, 최종 표본의 우세 성격 분포는 Balanced 26.5%, High neuroticism 16.8%, High agreeableness 16.1%, High conscientiousness 14.6%, High openness 13.1%, High extraversion 12.9%다.

### 칸별 통과율

두 번째 예비 생성은 정한 δ로 $`B`$명을 다시 생성하고 거부 검사(아래)를 통과했는지 기록한다. 칸 $`g`$는 사후층화 칸(성 × 5세 연령, 85세 이상은 한 칸 × 시도, 5.6절)이다.

```math
\hat a_g=\max\Big(0.5,\ \begin{cases}\bar{ok}_g & n_g\ge30\\ \bar{ok} & n_g<30\end{cases}\Big),\qquad w_r=\frac{w^{(0)}_r}{\hat a_{g(r)}}
```

예비 생성에 없던 칸은 전체 통과율 $`\bar{ok}`$를 사용한다. 기본 집단 추출이 $`w`$에 비례하므로 추출 확률 $`\pi_r\propto\pi^0_r/\hat a_{g(r)}`$를 한 번 적용한 것과 같다. 최소 시도 30명과 하한 0.5는 가정이다. 칸마다 200회 이상 시도하거나 수렴할 때까지 반복하지 않으며, 통과율 0인 칸을 별도 오류로 처리하지 않는다. 추가 보정항 $`\alpha`$도 적용하지 않는다. 예비 생성의 통과율은 `val_on`, `val_novl` 0.99944(칸 509개), `out_on` 0.99944(505개), `out_off` 0.99962(510개)다. 두 예비 생성은 재추출을 끈 상태이므로, 재추출이 거부 검사의 MatrAIx 속성 규칙에 주는 영향은 통과율에 반영되지 않는다.

이름이 지정된 검사 규칙 13개는 대부분 생성 과정에서 이미 성립하도록 생성되어 있어 실제로는 생성 규칙이 지켜졌는지 확인하는 역할을 한다. 생성 규칙만으로 막지 못하는 것은 센서스 기반 가상 가구의 동거 자녀 나이 차와, 생성 경로상 지켜지지 않는 일부 MatrAIx 금지 규칙이다. 검사는 출력 값(직접 정의 범주 포함)으로 하고 생성은 조건용 코드로 하므로, 직접 정의 범주는 MatrAIx 금지 규칙에 걸리지 않는다. 예를 들어 무급가족종사자는 생성 중에는 Self-employed로 조건이 걸리지만 검사에서는 Self-employed 조건의 규칙에 맞지 않는다. 스위치를 끈 실행에서는 MatrAIx 속성이 필요한 규칙 4개와 조건에 MatrAIx 속성이 있는 금지 규칙이 별도 경고 없이 제외된다. 대상 인구가 19세 이상이므로 13세 미만의 직무, 직급, 소득 제약은 포함하지 않는다.

```math
m=\min\Big(25000,\ \Big\lfloor\frac{N-n_{\text{통과}}}{\max(\bar{ok},\,0.5)}\times1.05\Big\rfloor+100\Big)
```

이고, 묶음마다 `make(m)` → 거부 검사 → 통과한 행 보관을 한다. 마지막에 통과한 행을 이어 붙여 앞에서부터 $`N`$명만 남긴다. 각 페르소나를 독립적으로 생성하므로 묶음 단위 거부는 개인 단위로 기각 후 다시 생성하는 것과 같은 분포를 따른다. 위반 수는 시도한 모든 행에서 규칙별로 더해 `stats.json`에 남긴다. 표본별 시도 수, 통과율, 위반 수는 다음과 같다.

### 고정 규칙 위반의 재추출

모순 규칙 묶음 1\~3(`krpersona/rules/set1.py`\~`set3.py`, 8장)의 강한 규칙을 어긴 사람은 거부하는 대신 MatrAIx 부분만 다시 추출한다(`generate/repair.py`의 `RepairRules`, `Gen4._repair`). 규칙 묶음 4는 재추출에 직접 사용하지 않는다. 다만 이 세트로 발견한 일부 문제는 생성 규칙에 반영했다(8.4절).

| 2 | 151 | 101 | 67 |
| 3 | 181 | 133 | 87 |

`_repair`는 한국 속성의 출력 값(직접 정의 범주와 `kr_*` 포함)과 MatrAIx 속성의 출력 값(비개발자의 개발 전용 속성은 Not applicable)으로 표를 생성하여 위반 행을 찾는다. 위반 행은 한국 코드를 고정한 채 MatrAIx 노드 1,087개를 모두 다시 추출하고(`sample_rest`), `_multi`로 다중언어를 다시 정한 뒤 다시 검사한다. 이를 최대 40번 반복한다(`repair_rounds = 40`, 가정). 40번 뒤에도 위반이 남은 행은 유지한다. 거부 검사는 위의 `own_masks.rules`만 보므로 이 행들은 버려지지 않고 출력된다. 재추출은 위반에 관련된 속성만이 아니라 그 행의 MatrAIx 부분 전체를 다시 추출하므로, 성공한 행의 MatrAIx 부분은 한국 값이 주어졌을 때의 MatrAIx 분포를 규칙을 지키는 조합으로 제한한 분포에서 추출된 것과 같다. 묶음별 회차마다의 위반 행 수는 `stats.json`의 `repair`에 남는다: `val_on`과 `val_novl`은 첫 검사에서 3행이 걸렸고 한 번 재추출한 뒤 0행, `out_on`은 7행이 걸려 40번 뒤에도 2행이 남았다(두 행 모두 세트 2 규칙 `R2-PS-H07` "최우선 가치가 해당 가치 척도에서 낮음"에 걸렸다. 이 규칙은 MatrAIx 속성 `val_community`도 참조하므로 재추출 대상이지만, 두 행의 위반은 한국 속성에서 나온다: KGSS 응답 범주가 Security 하나로만 대응되는데 가치 문항 `val_security_stability`가 Minor여서, 낮게 평가한 가치를 빼면 빈 집합이 되고 원래 집합으로 되돌리는 규칙(`Gen4._kgss`)에 따라 Security가 남았다. 그래서 MatrAIx 부분을 다시 추출해도 해소되지 않는다, 8장). `out_off`는 MatrAIx 속성이 없어 재추출을 하지 않는다.

## 7.9 출력

일반 생성은 `python -m krpersona.generate.run 인원 시드 on또는off 결과이름`으로 실행한다. 선택적인 다섯 번째 인수는 사전 보정 인원이며 기본값은 50,000명이다. `on`은 속성 1,311개, `off`는 한국 속성 242개를 출력하고, 두 경우 모두 식별자 `persona_id`가 추가된다.

생성 입력은 산출물 폴더의 파일을 우선 참조하고, 파일이 없으면 `bundle/`에서 불러온다. 센서스 사후층화 목표, 모자 나이 차이와 사회단체 참여율은 `census/aggregates.pkl`을 사용하므로 일반 생성에 원자료는 필요하지 않다. 기본 저장 위치는 저장소의 `artifacts/samples/결과이름/`이다. 설치와 결과 확인 절차는 README에 있다.

`bundle/`은 전체 자료 모형에 대한 입력 묶음이며 80% 검증용 모형을 포함하지 않는다. 건강 모형에는 응답자 설계행렬을 저장하지 않고, 소득은 구간별 200개 가중 분위값, 가족의 비동거 자녀 나이 차이와 가중치는 5명 이상 묶음의 평균, 센서스 모자 나이 차이는 빈도표로 저장한다. 추정 단계부터 이 형식을 적용하므로 묶음 작성 시에는 추가 변환 없이 복사한다. 이 장의 수치는 같은 저장 방식을 적용한 모형으로 생성한 결과이며, 최종 표본은 `bundle/`과 동일한 전체 자료 모형을 사용한다. 저장 구조와 공개 검토 범위는 10.13절에 제시하였다.

### 파일

`run.py <N> <seed> <on|off> <표본 이름> [B]`는 `artifacts/samples/<표본 이름>/`에 다음 파일을 저장한다.

| 파일 | 내용 |

### 내부 값

`internal.parquet`은 검증(9장)을 위해 속성 파일에 없는 값을 `persona_id`와 함께 저장한다: 정확한 나이(`age`), 성(`sex`), 시도(`sido`), 가구원 수(`k`), 가구주와의 관계(`rel`), 가구구분(`hkind`), 원화 가구소득(`income`, 만원/년), 본인 임금 구간(`wage_band`, 임금근로자가 아니면 −1), 소득 4분위(`inc4`), 우울 및 불안 잠재 점수(`xi_d`, `xi_a`), PHQ-9, GAD-7 합계(`phq`, `gad`), 자녀를 생성한 경로(`kid_src`)와 자녀 수(`n_kids`), 건강 블록의 범주 번호 8개(`h_*`), KGSS 블록의 범주 번호 73개(`k_*`), 성격 요인 점수 5개(`e_O`\~`e_N`), 가치 점수 10개(`v_0`\~`v_9`)다. 센서스 기록 번호, 나머지 센서스 변수, 측면 점수, 자녀 나이, 비개발자의 숨은 MatrAIx 값은 어디에도 저장하지 않는다. 잠재 점수는 검증을 위해 내부 파일에만 보관한다. 속성 파일은 연령대만 있고 정확한 나이와 시도는 없다(노출 위험은 5.5절).

### MatrAIx 통합 형식

`personas_matraix.parquet`은 MatrAIx의 `AttributeCodec`과 `UNIFIED_SCHEMA`를 수정하지 않고 사용한다. 코덱은 `persona_codes.schema.json`의 MatrAIx 출력 속성 1,290개를 그래프 순서로 불러오며, 열 수가 MatrAIx `schema.py`의 `ATTRIBUTE_COUNT = 1290`과 다르면 오류를 발생시킨다. 따라서 새 한국 속성 21개는 이 파일에 없다. 값이 MatrAIx 범주이면 코드(4비트 두 개를 한 바이트에, `attributes` 645바이트)로, 없으면 null 비트(`null_bitmap` 162바이트, 스위치를 끈 실행의 MatrAIx 부분)로, 범주에 없는 값(위 표)이면 `attribute_overrides`에 `(field_index, value)`로 기록한다. 덮어쓴 칸의 코드 바이트는 0이므로, `attribute_overrides`를 반영하지 않는 도구는 그 칸을 첫 범주로 해석한다. `source`는 `kr_persona`, `source_record_id`는 `persona_id`, `has_description`은 거짓이고 설명, 근거, 메타데이터 열은 비어 있다. 압축은 zstd다. `persona_codes.schema.json`에는 `format`과 `columns`(속성 id와 범주 목록)만 있고, MatrAIx `codes_schema()`가 사용하는 `format_version`, `dtype`, `shape`, `packing` 등은 없다.

## 7.10 프롬프트 렌더링

### MatrAIx 렌더러가 빼는 값

MatrAIx는 페르소나의 속성 값을 에이전트 프롬프트의 프로필로 바꿀 때 `src/matraix/persona_dimension_catalog.py`의 `collect_dimension_items`를 사용한다. 이 함수는 다음 값을 프로필에 포함하지 않는다.

1. id가 외부 자료 접두사로 시작하거나 분류가 External로 시작하는 속성(1,290개 가운데 해당 없음).
2. 값이 null이거나, 앞뒤 공백을 지운 소문자 문자열이 `_NULLISH` = {"", none, n/a, na, null, undefined, none notable, not applicable, prefer not to say, no coding activity, not a developer, no interest, unknown}에 드는 값.
3. 값(또는 그 문자열)이 `dimensions.json`의 `defaultValue`와 같은 값. 1,290개 가운데 1,126개에 기본값이 있다(예: 성격 측면 Average, `gender_identity` Prefer not to say).

또 환경 변수 `MATRAIX_PERSONA_PROFILE_MAX_CHARS`로 길이 상한을 걸 수 있고(기본은 없음), 주 언어로 답하라는 문장은 상한이 없을 때만 추가한다. 한국 페르소나에는 None, Not applicable, Not a developer, Never used 같은 값과 기본값과 같은 값이 많다. 특히 비개발자의 개발 관련 속성 133개(7.6절)는 대부분 이런 값이다. MatrAIx 렌더러가 한 사람에게서 빼는 속성 수는 `val_on` 처음 5,000명에서 평균 670.3개(최소 548, 최대 743), 1,311개의 51.1%이고, `out_on`에서 평균 670.7개(519\~753), 51.2%이다. 한국 페르소나 렌더러는 이 값들을 모두 전달한다.

### 한국 렌더러 `krpersona/render/render.py`

한국 렌더러는 MatrAIx 렌더러와 같은 함수 이름과 인수(`load_dimension_catalog`, `collect_dimension_items`, `build_dimension_narrative`, `build_template_context_extras`, `overlay_labels_from_persona_path`)와 같은 출력 형식("### 절 제목" 다음 "- 이름: 값" 줄)을 사용한다. 다른 점은 다음과 같다(모듈 설명문의 목록과 같다).

| 항목 | MatrAIx | 한국 렌더러 |
|---|---|---|
| 값을 빼는 규칙 | 위의 1\~3과 길이 상한 | 없음. 모든 속성을 넣음 |
| 값 | 문자열로 변환하여 넣음 | 그대로 넣음(직접 정의 범주 포함) |
| 빈 값(null, 빈 문자열, nan, null 문자열) | 뺌 | 생성 오류로 보고 `RenderError` |
| 절 구성 | 10개 절과 Other attributes | 같음. 분류 Health: Mental(새 한국 속성 4개)을 Lifestyle & health에 넣음(MatrAIx라면 Other attributes) |
| 성격과 가치 절 | 속성 줄만 | 첫 줄에 범주의 뜻을 적은 `LEVEL_GUIDE` |
| 주 언어 문장 | 길이 상한이 없을 때만 | `primary_language`가 있으면 항상 |
| 길이 상한 `max_chars` | 적용 | 인수만 받고 무시 |
| 속성 설명 파일 | `persona/schema/dimensions.json` | `krpersona/render/dimensions_kr.json` |

`LEVEL_GUIDE`는 "Levels are relative to Korean adults."로 시작해 성격 범주는 아래 6.5%, 다음 24%, 가운데 39%, 다음 24%, 위 6.5%, 기본 가치 범주는 5.5%, 23%, 43%, 23%, 5.5%라고 기록한다. 이 비율은 성격 경계 ±0.51, ±1.51과 가치 경계 ±0.57, ±1.60(`blocks/values.py`의 `CUTS`)을 표준정규분포에 적용한 값(6.55%, 23.95%, 38.99%와 5.48%, 22.95%, 43.14%)을 반올림한 것이다. 생성된 점수의 실제 분포가 표준정규에서 벗어나면 출력 비율도 이 문장과 다를 수 있다(9장).

`dimensions_kr.json`은 MatrAIx `persona/schema/dimensions.json`을 복사한 것이다. 최상위 항목과 처음 1,290개 속성은 원본과 같고, 하나만 고쳤다. `cog_assertiveness`(의사소통 방식의 자기주장)의 이름이 성격의 `big5_assertiveness`와 같은 "Assertiveness"여서 "Assertiveness (communication style)"로 바꿨다. 끝에 새 한국 속성 21개(id, 이름, 분류, 설명, 범주, `defaultValue` 없음)를 더해 1,311개다. 새 속성의 분류는 Worldview: Beliefs, Health: Mental, Demographic: Core(`kr_subjective_class`), Personality: Relationships(`kr_confidants`)다. 기존 속성의 범주 목록에는 한국 직접 정의 범주(Unpaid family worker, Not a developer, 한국 종교 등)를 더하지 않았다. 렌더러는 값을 검사하지 않으므로 출력에는 영향이 없지만, 이 파일은 완전한 범주 사전이 아니다.

### 렌더링 점검

`validate/render_check.py <personas.parquet> <out.pkl>`(`scripts/07_validate.sh`가 `val_on`과 `out_on`에 실행)는 네 항목을 점검한다. (1) 처음 5,000명(표본이 작으면 전부)에서 한국 렌더러가 빠뜨린 속성 수와 MatrAIx 렌더러가 빠뜨린 속성 수. (2) 처음 200명을 MatrAIx 템플릿 `persona_system.md.j2`(Jinja2, 정의되지 않은 변수는 오류)로 실제 프롬프트로 생성하여 "- "로 시작하는 줄 수가 속성 수와 같은지. (3) 고정 예시: 연령대 45-54, 직무 Teaching, 여성인 첫 사람의 프롬프트를 `artifacts/validation/reference_teacher_45-54.md`로 저장. 예시는 조건에 맞는 첫 사람(1966\~1975년생)을 사용한다. (4) 처음 2,000명에서 MatrAIx 렌더러가 속성마다 빠뜨리는 비율. 결과는 두 표본 모두 1인당 속성 1,311개, 한국 렌더러 누락 0개, 템플릿 줄 점검 통과 비율 1.0이고, 예시 프롬프트는 `val_on`에서 42,911자(`krp-11-0000041`), `out_on`에서 42,793자(`krp-1-0000136`)다. 점검 (1)은 null이 아닌 값만 세므로 null이 있었다면 누락으로 잡히지 않는다. 렌더링된 프로필을 모델이 이해하는지 묻는 응답 실험은 수행하지 않았다.

## 7.11 한계

- 원소가 둘 이상인 집합 안의 선택(미혼의 연애, 약혼, 60세 미만 비취업 남녀의 Unemployed와 Homemaker, 경력, 직급, 생애단계 등)은 한국 자료가 아니라 MatrAIx 확률이 정한다.
- 한국 속성은 MatrAIx의 γ를 그대로 사용하므로, 지금은 작용하지 않는 뒤집은 연결의 가중치까지 축소에 들어간다.
- 대상이 한국 속성인 CPT의 정해지지 않은 부모는 조건부 분포가 아니라 주변 기본 확률로 평균을 산출한다. `att_ai`–`tech_savviness` 관계는 CPT를 뒤집지 않으므로 사라진다.
- 범주 없음 코드인 부모가 하나라도 있으면 CPT 전체가 꺼진다. 주 언어 Korean 때문에 영어 능력과 외국어 11개의 CPT, 주 언어를 조건으로 하는 MatrAIx 금지 규칙 49개가 모두 작동하지 않는다. Not applicable, Other, Not a developer에서 나가는 연결도 모두 인수 1이다.
- 금지 규칙은 행의 모든 값을 지우면 그 행에서 무시되므로 보장되지 않는다. 충돌하면 나중에 곱하는 규칙은 제외된다(예: 분야 Software & AI인 비개발자의 코딩 능력).
- 집합 안 배분에서 금지 규칙이 허용 값을 모두 지우면 기본 확률만으로 고르므로 그 행에서는 부모 정보도 사용되지 않는다.
- 조건이 대상보다 늦게 추출되는 금지 규칙은 작동하지 않는다. 대상이 한국 속성인 MatrAIx 금지 규칙 6개, 충돌 수정 금지 규칙의 반대 방향 60개, 컴파일한 규칙 마스크의 일부가 그렇다.
- MatrAIx 금지 규칙의 유지 또는 폐기 분류는 기본 생성기의 한 번의 예비 생성(6만 명)에서 위반이 있었는지로 정한 것이고 `Gen4`로 다시 하지 않았다. 유지한 84개 가운데 39개는 미성년 연령 조건뿐이라 효과가 없고, 현재 한국 속성이 대상이지만 사전 분류에서 빠진 8개는 분류되지 않았다.
- 거부 검사는 출력 값으로, 생성은 조건용 코드로 하므로 직접 정의 범주는 MatrAIx 금지 규칙 검사에 걸리지 않는다.
- `multilingualism`은 그 값을 조건으로 자식 6개, 평생 언어 수 규칙, 소수 언어 예산 규칙을 계산한 뒤에 덮어쓰기한다. 언어 마스크는 언어 수의 위쪽만 제한한다.
- 주요 외국어 11개는 `multilingualism`의 제약을 받지 않고 소수 언어 38개는 받는 비대칭이 MatrAIx 언어 예산 규칙의 조건(주 언어)에서 생긴다.
- 성격에서 파생한 37개의 상관 $`r`$, MBTI, 사교 에너지 부하량 0.7, 같은 측면 상관 0.6, 극단 조정은 모두 가정이다. 파생 속성은 한국 속성인 부모 124개와의 연결을 잃는다(예: `skill_leadership`과 직급).
- 비동거 자녀는 출산 기록이 있는 사람과 61세 이상만 생성한다. 기록이 없는 61세 미만 결혼 경험자(가구주와 배우자 쌍이 아닌 기혼 남성 등)는 동거 자녀만 집계한다. 조부모는 가구 명부의 손자녀로만 판정한다.
- 비취업자의 경력은 자료 없이 나이로 허용되는 범위에서 MatrAIx 확률이 정한다.
- 개발자 여부는 직업 대분류 2의 취업자만 모형으로 정하고, 취미, 학생, 과거 개발자 범주는 생성하지 않는다. 비개발자의 개발 전용 속성 50개는 출력만 Not applicable이고 숨은 값이 자손에 영향을 미친다.
- δ는 거부 전 예비 표본에서 한 번 정하고, 칸별 통과율은 시도 30명 미만이면 전체 통과율, 하한 0.5로 한 번만 적용한다. 반복 보정과 보정항 $`\alpha`$는 구현되지 않았다. 우세 성격의 High 다섯 범주는 MatrAIx 기본 확률에 맞추지 않는다.
- 재추출 40번 뒤에도 고정 규칙을 어기는 행은 버리지 않고 출력한다. 재추출에 사용하는 규칙이 참조하는 열은 한 줄 표의 실행으로 찾으므로 일부 열을 놓칠 수 있다.
- 규칙 묶음 1\~3은 생성(충돌 수정 금지 규칙, 컴파일한 규칙 마스크, 재추출)에 쓰였으므로 검증에는 독립적이지 않다. 묶음 4의 규칙 3개도 사전 검토와 생성 규칙 보완에 사용했다(8장, 9장).
- 기준 연도가 2020년이어서 성장기 연대 창이 2020년에서 잘리고, 75세 이상은 모두 Silent, 70세 이상은 모두 1960s-70s다.
- 두 난수 생성기가 같은 시드로 생성되어 같은 난수열을 다른 위치에서 사용한다.
- 스위치를 끈 실행도 δ와 칸별 통과율은 MatrAIx 부분을 생성한 예비 생성에서 정하고, 실제 거부 검사에서는 MatrAIx 속성이 필요한 규칙이 제외된다.
- `personas_matraix.parquet`에는 새 한국 속성이 없고, 덮어쓴 칸의 코드는 0이며, 코덱 스키마는 MatrAIx 형식의 일부 항목만 담는다. `ATTRIBUTE_COUNT = 1290` 때문에 이 그래프 판에만 맞는다.
- `dimensions_kr.json`의 범주 목록은 한국 직접 정의 범주를 담지 않는다. 렌더러의 `LEVEL_GUIDE` 비율은 표준정규를 가정한 값이다.
- `sampler.py`의 `placeholder` 인수는 사용되지 않는다.
- `tests/test_sampler.py`는 한국 속성이 없을 때 MatrAIx 샘플러와의 일치를 확인한다. 한국 속성과 블록 모형을 결합한 전체 생성 과정의 동등성을 검증하는 시험은 아니다.
